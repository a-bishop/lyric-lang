# lyric-lang — project context

This document is a handoff from a design conversation. It captures all architectural decisions, code, and rationale so a new Claude Code (or other coding agent) session can pick up immediately without re-litigating earlier choices.

---

## What this project is

An ingestion pipeline that takes song lyrics in a foreign language and generates a structured language learning plan — vocabulary, grammar patterns, cultural notes, exercises, and a spaced review schedule. The song use case is the MVP, but the architecture is designed to generalise to any unstructured input that signals learning intent.

## MVP scope (v1)

- **Input:** HTTP POST with song lyrics + metadata (title, artist, source language, target language)
- **Output:** JSON response with extracted concepts + full learning plan
- **No UI** — pipeline only, tested via curl / HTTP client
- **Single Worker, synchronous** — extract and plan in one request, no queue yet
- **All four artifacts stored in D1:** raw input, extracted concepts, generated plan, raw LLM logs

---

## Stack decisions

| Concern           | Choice                                              | Rationale                                                                      |
| ----------------- | --------------------------------------------------- | ------------------------------------------------------------------------------ |
| Runtime           | Cloudflare Workers                                  | Zero cold starts, fast DX, free at hobby scale, good learning project          |
| Language          | TypeScript                                          | Primary skill, first-class on Workers                                          |
| Router            | Hono                                                | Lightweight, Express-like, Workers-native                                      |
| Database          | Cloudflare D1 (SQLite)                              | Sufficient for MVP, zero config, co-located with Worker                        |
| ORM               | Drizzle                                             | Type-safe, D1 adapter, great DX                                                |
| LLM client        | Vercel AI SDK (`ai` + `@ai-sdk/anthropic`)          | Provider-agnostic, `generateObject` handles structured outputs cleanly via Zod |
| Schema validation | Zod                                                 | Used by AI SDK for structured outputs; single source of truth for types        |
| LLM model         | `claude-sonnet-4-5` (via `ANTHROPIC_MODEL` env var) | Good balance of quality and speed; swappable                                   |

### Why Cloudflare over AWS

Faster iteration for a learning project. AWS equivalent map for future reference:

- Workers → Lambda
- Queues → SQS + Lambda trigger
- D1 → RDS Aurora Serverless
- R2 → S3
- Durable Objects → DynamoDB + ElastiCache
- Workflows → Step Functions

### Why Vercel AI SDK over Anthropic SDK directly

`generateObject` wraps the tool_choice structured output pattern cleanly. Zod schemas replace raw JSON Schema objects. Provider swap (e.g. to OpenAI) is a one-line change. The Anthropic SDK is still the underlying transport via `@ai-sdk/anthropic`.

### `src/pipeline/extract.ts`

```typescript
import { createAnthropic } from "@ai-sdk/anthropic";
import { generateObject } from "ai";
import { z } from "zod";
import { PROMPT_VERSIONS } from "./prompts";
import type { SongInput, ExtractedConcepts, Env } from "../types";

const VocabItemSchema = z.object({
  term: z.string(),
  type: z.enum(["slang", "idiom", "standard", "colloquial"]),
  register: z.enum(["formal", "informal", "vulgar"]),
  definition: z.string(),
  exampleLine: z.string().describe("Verbatim lyric line containing the term"),
  difficulty: z.union([z.literal(1), z.literal(2), z.literal(3)]),
});

const GrammarPatternSchema = z.object({
  pattern: z.string(),
  explanation: z.string(),
  exampleLine: z.string(),
});

const ExtractedConceptsSchema = z.object({
  level: z.enum(["A1", "A2", "B1", "B2", "C1", "C2"]),
  vocabulary: z.array(VocabItemSchema),
  grammarPatterns: z.array(GrammarPatternSchema),
  culturalNotes: z.array(z.string()),
});

export interface ExtractionResult {
  concepts: ExtractedConcepts;
  log: {
    promptVersion: string;
    modelId: string;
    inputTokens: number;
    outputTokens: number;
    durationMs: number;
    rawRequest: string;
    rawResponse: string;
  };
}

export async function extractConcepts(song: SongInput, env: Env): Promise<ExtractionResult> {
  const anthropic = createAnthropic({ apiKey: env.ANTHROPIC_API_KEY });
  const model = env.ANTHROPIC_MODEL;

  const prompt = `You are a linguistics expert specializing in language learning.

Analyze these song lyrics and extract learning material for a ${song.targetLanguage} speaker learning ${song.sourceLanguage}.

Song: "${song.title}" by ${song.artist}${song.genre ? ` (${song.genre})` : ""}

Lyrics:
${song.lyrics}

Extract vocabulary (prioritizing slang, idioms, and colloquial terms), grammar patterns, cultural notes, and estimate the CEFR level.`;

  const start = Date.now();

  const result = await generateObject({
    model: anthropic(model),
    schema: ExtractedConceptsSchema,
    prompt,
  });

  const durationMs = Date.now() - start;

  return {
    concepts: result.object,
    log: {
      promptVersion: PROMPT_VERSIONS.extract,
      modelId: model,
      inputTokens: result.usage.promptTokens,
      outputTokens: result.usage.completionTokens,
      durationMs,
      rawRequest: JSON.stringify({ model, prompt }),
      rawResponse: JSON.stringify(result.rawResponse),
    },
  };
}
```

### `src/pipeline/plan.ts`

```typescript
import { createAnthropic } from "@ai-sdk/anthropic";
import { generateObject } from "ai";
import { z } from "zod";
import { PROMPT_VERSIONS } from "./prompts";
import type { SongInput, ExtractedConcepts, LearningPlan, Env } from "../types";

const ExerciseSchema = z.object({
  type: z.enum(["gap-fill", "translation", "multiple-choice", "free-write"]),
  prompt: z.string(),
  answer: z.string(),
  hint: z.string().optional(),
});

const ReviewScheduleSchema = z.object({
  initialReviewDays: z.number(),
  intervals: z.array(z.number()).describe("Subsequent review intervals in days e.g. [3, 7, 21]"),
});

const LearningUnitSchema = z.object({
  order: z.number(),
  title: z.string(),
  focusType: z.enum(["vocabulary", "grammar", "culture", "pronunciation"]),
  items: z.array(z.string()).describe("Term or pattern names from extracted concepts"),
  exercises: z.array(ExerciseSchema),
  reviewSchedule: ReviewScheduleSchema,
});

const LearningPlanSchema = z.object({
  summary: z.string(),
  estimatedHours: z.number(),
  units: z.array(LearningUnitSchema),
});

export interface PlanResult {
  plan: LearningPlan;
  log: {
    promptVersion: string;
    modelId: string;
    inputTokens: number;
    outputTokens: number;
    durationMs: number;
    rawRequest: string;
    rawResponse: string;
  };
}

export async function generatePlan(song: SongInput, concepts: ExtractedConcepts, env: Env): Promise<PlanResult> {
  const anthropic = createAnthropic({ apiKey: env.ANTHROPIC_API_KEY });
  const model = env.ANTHROPIC_MODEL;

  const prompt = `You are a language learning curriculum designer.

Create a structured learning plan for a ${song.targetLanguage} speaker learning ${song.sourceLanguage} through this song.

Song: "${song.title}" by ${song.artist}
Estimated level: ${concepts.level}

Extracted concepts:
${JSON.stringify(concepts, null, 2)}

Design 3-5 learning units. Each unit should cluster related concepts, include 2-3 exercises grounded in the actual lyrics, and have a realistic spaced review schedule.`;

  const start = Date.now();

  const result = await generateObject({
    model: anthropic(model),
    schema: LearningPlanSchema,
    prompt,
  });

  const durationMs = Date.now() - start;

  return {
    plan: result.object,
    log: {
      promptVersion: PROMPT_VERSIONS.plan,
      modelId: model,
      inputTokens: result.usage.promptTokens,
      outputTokens: result.usage.completionTokens,
      durationMs,
      rawRequest: JSON.stringify({ model, prompt }),
      rawResponse: JSON.stringify(result.rawResponse),
    },
  };
}
```

### `src/index.ts`

```typescript
import { Hono } from "hono";
import { drizzle } from "drizzle-orm/d1";
import { eq } from "drizzle-orm";
import { nanoid } from "nanoid";
import { jobs, songInputs, extractedConcepts, learningPlans, llmLogs } from "./db/schema";
import { extractConcepts } from "./pipeline/extract";
import { generatePlan } from "./pipeline/plan";
import type { Env, SongInput } from "./types";

const app = new Hono<{ Bindings: Env }>();

app.post("/ingest", async (c) => {
  const db = drizzle(c.env.DB);
  const jobId = nanoid();
  const now = new Date();

  let input: SongInput;
  try {
    input = await c.req.json<SongInput>();
    if (!input.lyrics || !input.sourceLanguage || !input.targetLanguage) {
      return c.json({ error: "lyrics, sourceLanguage, targetLanguage are required" }, 400);
    }
  } catch {
    return c.json({ error: "Invalid JSON body" }, 400);
  }

  await db.insert(jobs).values({
    id: jobId,
    status: "processing",
    createdAt: now,
    updatedAt: now,
  });

  await db.insert(songInputs).values({
    id: nanoid(),
    jobId,
    title: input.title ?? "Unknown",
    artist: input.artist ?? "Unknown",
    sourceLanguage: input.sourceLanguage,
    targetLanguage: input.targetLanguage,
    lyrics: input.lyrics,
    genre: input.genre ?? null,
    createdAt: now,
  });

  try {
    const { concepts, log: extractLog } = await extractConcepts(input, c.env);

    await db.insert(extractedConcepts).values({
      id: nanoid(),
      jobId,
      promptVersion: extractLog.promptVersion,
      data: JSON.stringify(concepts),
      createdAt: new Date(),
    });

    await db.insert(llmLogs).values({
      id: nanoid(),
      jobId,
      stage: "extract",
      ...extractLog,
      createdAt: new Date(),
    });

    const { plan, log: planLog } = await generatePlan(input, concepts, c.env);

    await db.insert(learningPlans).values({
      id: nanoid(),
      jobId,
      promptVersion: planLog.promptVersion,
      data: JSON.stringify(plan),
      createdAt: new Date(),
    });

    await db.insert(llmLogs).values({
      id: nanoid(),
      jobId,
      stage: "plan",
      ...planLog,
      createdAt: new Date(),
    });

    await db.update(jobs).set({ status: "complete", updatedAt: new Date() }).where(eq(jobs.id, jobId));

    return c.json({ jobId, concepts, plan }, 201);
  } catch (err) {
    await db
      .update(jobs)
      .set({
        status: "failed",
        errorMessage: err instanceof Error ? err.message : String(err),
        updatedAt: new Date(),
      })
      .where(eq(jobs.id, jobId));

    throw err;
  }
});

app.get("/jobs/:id", async (c) => {
  const db = drizzle(c.env.DB);
  const jobId = c.req.param("id");

  const [job] = await db.select().from(jobs).where(eq(jobs.id, jobId));
  if (!job) return c.json({ error: "Not found" }, 404);

  if (job.status !== "complete") {
    return c.json({ jobId, status: job.status });
  }

  const [plan] = await db.select().from(learningPlans).where(eq(learningPlans.jobId, jobId));
  const [concepts] = await db.select().from(extractedConcepts).where(eq(extractedConcepts.jobId, jobId));

  return c.json({
    jobId,
    status: job.status,
    concepts: JSON.parse(concepts.data),
    plan: JSON.parse(plan.data),
  });
});

export default app;
```

## Key design decisions worth preserving

**Prompt versioning** — every LLM call stores its `promptVersion` string alongside the output. When prompts improve, old results are traceable to the version that generated them. Current versions: `extract-v1`, `plan-v1`.

**LLM log table** — raw request and response JSON stored for every call. This is the eval dataset for future prompt improvement. Don't remove it to save space; it's cheap and invaluable.

**Zod as single source of truth** — the Zod schemas in `extract.ts` and `plan.ts` define the contract. The TypeScript interfaces in `types.ts` mirror them manually for now. A natural cleanup: replace the interfaces with `z.infer<typeof Schema>` exports from the pipeline files.

**`createAnthropic` pattern** — the AI SDK provider is instantiated with the API key from the Worker `env` binding rather than `process.env`. This is intentional — Cloudflare Workers don't have `process.env` at runtime, env vars come through the `Env` binding.

## Deferred to v2+

- **Cloudflare Queue** for async processing (needed when adding audio input or chaining 3+ LLM calls — current two-call pipeline fits in the Worker timeout comfortably)
- **Audio input** via Whisper transcription — goes through Queue from day one when added
- **Knowledge graph / prereq tracking** — concepts table with edges, enables "don't re-teach subjunctive"
- **Multi-tenant** — D1 per-tenant isolation pattern, Cloudflare Access for auth
- **FSRS spaced repetition** — replace hardcoded intervals with proper algorithm
- **Eval harness** — use llm_logs table to run prompt versions against a golden set
- **Web UI** — Hono serves static assets natively, or deploy a separate Pages project
